# 知乎 API 接入指南

本项目将静态阅读器和服务端凭据分开部署。完整接口实现见 [后端说明](../backend/README.md)，FC 配置与通过标准见 [部署说明](FC_DEPLOYMENT.md)。

## 当前接入能力

| 能力 | 项目入口 | 依赖 |
| --- | --- | --- |
| 知乎登录与基础资料 | 页面“知乎登录” | 后端 APP_ID、APPKEY，登记 Pages 回调 |
| 活动故事目录和节选 | 新增入梦书 → 知乎故事 | 后端转发活动接口，目录本身无需 Access Secret |
| 知乎搜索 | 搜索故事 | 登录会话及后端 Access Secret |
| 直答线索分析 | 为片段创建分析任务 | 登录会话及后端 Access Secret；产物为分析报告 |
| 自动生成可玩故事 | 制作流程演示 | 目前使用既有示例内容，尚未实现任意小说生成 |

故事 ID 按字符串处理，不与圈子 ID、OAuth 应用 ID 混用。活动接口返回的节选不是原作全文；搜索摘要也不能当作已获得授权的完整正文。

## 凭据区别

| 凭据 | 用途 | 项目配置 |
| --- | --- | --- |
| 活动分配 APP_ID | 标识 OAuth 应用 | `ZHIHU_OAUTH_APP_ID` |
| 活动分配 APPKEY | 服务端兑换授权码 | `ZHIHU_OAUTH_APP_KEY` |
| 开放平台 Access Secret | 搜索、直答等开放能力 | `ZHIHU_ACCESS_SECRET` |
| 社区 API 的 app_key / app_secret | 社区接口 HMAC 请求签名 | 本项目阅读与登录不使用这组社区凭据 |

社区签名文档中的 app_key 是个人主页 token，app_secret 是申请的应用密钥。按文档为每次社区请求生成 HMAC-SHA256 和 Base64 签名，附带时间戳、请求 ID 等请求头；它与 OAuth 用户同意授权不是同一种鉴权。不要用圈子 ID 替代任何应用凭据。

本地可由应用读取 `.env`；线上只在 FC 环境变量中配置。不要使用 `VITE_*` 存放密钥，Vite 变量会进入浏览器代码。

## OAuth 流程

浏览器向 `/api/auth/start` 申请授权地址 → 浏览器跳转知乎 → 知乎返回 Pages 的 `oauth-callback.html` → 页面将授权码交给 FC `/api/auth/exchange` → FC 兑换令牌并读取账号资料 → 返回短期应用会话。

知乎应用密钥和 OAuth Token 留在后端；前端保存的短期应用会话位于当前标签页 `sessionStorage`。应用自己的 state、verifier 和签名请求证明用于绑定这次登录请求，不能据此推断知乎支持标准 OAuth 2.0 PKCE。

登录成功只证明本人授权和账号资料链路可用，不代表内容生成、共享任务或云存档已经可用。线上需完成一次本人授权、刷新、退出和重新登录测试。

阅读、书架、导入导出、存档与设置入口统一要求登录授权；本地开发可使用模拟登录。前端在页面打开、重新获得焦点或变为可见时检查 `/api/session`，页面可见期间每 60 秒再次检查。接口返回 401、退出登录或会话检查失败后关闭受限入口并返回首页，保留本地书架、存档与对话队列；恢复网络并确认授权后可继续。游客仍可调整首页声音和查看作品说明。

## 请求与额度

搜索和分析使用本服务的每日预算，默认分别为 100 次和 20 次，可由服务器环境变量调整。这不是知乎账户的实时共享剩余额度。目录/详情缓存一小时，搜索/分析缓存半小时，失败不自动重试；FC 多实例间的预算和任务状态尚不共享。
