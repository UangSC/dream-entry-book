# 文档审查与设计决策

审查日期：2026-09-12。范围：`docs/` 全部原有文档、`zhihu/` 的相关官方资料、9 份官方图像。完成文件与资料核对及图像查看；未调用线上 API、未复跑旧游戏，未生成新美术。

## 总体判断

“把阅读变成短篇人生”的方向成立。此前主要问题是风格与资产不匹配、范围大于首版需要、若干历史实验被写成平台保证，以及玩法、数据和发布流程没有闭合。

本轮默认采用**清透二次元梦境书屋 + 官方刘看山 + 预织短篇多结局**。以下决策属于助手基于用户授权作出的设计选择，已同步进正文；不是用户已逐项确认的偏好。后续可按试玩结果调整。

## 已作出的默认决策

| 事项 | 默认选择 | 理由与重新评估条件 |
|---|---|---|
| 书名 | 保留《入梦书》 | 与“入梦”行为一致，不依赖官方 IP 授权命名 |
| 二次元方向 | 清透、温柔、带轻微奇幻；不强制恋爱 | 容纳不同原作，也适合白色刘看山 |
| 梦斋形态 | 云光中的现代奇幻书屋 | 电脑动画可自然融入；不必增加古代转译 |
| 人类角色立绘 | 首版不做；姓名牌与角色卡承担识别 | 先验证互动故事；未来只为固定精选故事做一致角色组 |
| 首篇题材 | 现代轻奇幻/轻悬疑优先，场景集中 | 首批资产可复用；若无适合节选再调整题材 |
| 数值系统 | 最多 2 资源、1 关系；优先事实标记 | 避免短篇变成数值管理，方便验证因果 |
| 结局数量 | 首篇 2 个有实质差异的结局 | 及时验证“选择有分量”，避免先做大量线性内容 |
| 生成方式 | 制作端两步生成，审读后公开 | 零凭证门槛、可离线、上线故障更少 |
| 生成模型 | zhida-fast-1p5 作为首次制作候选 | 本地资料支持且有历史尝试；质量不足再比较 thinking |
| 新梦等待 | 首版不伪造等待；在线模式后置 | 已预生成的内容应立即进入 |
| 原文导流 | 梦醒页清楚的独立按钮 | “醒来”不等于跳出游戏；读者可选择 |
| 静态资源 | 用户逐张生成，先 BG_GATE 定调 | 避免整批返工；提示词已可直接使用 |

## 仍需外部事实，而非继续空谈的设计选择

- **具体故事**：需读取候选正文，确认人物、局部闭环、改编与分发使用依据；本轮未选定作品。此项不阻塞梦门图和引擎设计。
- **官方资产适用范围**：当前目录有文件，没有完整的 IP 使用许可附件。采用赛事内使用的保守工作范围，并在发布前记录对应条款；不推断可商用或赛后继续公开。
- **上线与赛事**：本地 2026-09-03 资料写报名至 9 月 13 日 00:00、提交至 9 月 15 日 10:00；未核验当前活动页面或用户报名状态。若按此参赛，应优先完成首版及提交材料。
- **素材工具与画面效果**：首张图生成后再核对实际观感、输出尺寸和工具许可；本轮不代替用户开通付费工具。

无需因上述事项暂停本轮文档工作。具体素材生成结果、作品来源许可、线上可用状态不能由设计决策代替事实。
