# 律动与心跳（视听同步契约）

2026-09-13 用户要求：律动仅用于梦斋。入梦阅读与终幕关闭脉冲采样循环，画面缩放/亮度归一，文字保持稳定；夜间萤火虫和白昼落叶是独立环境粒子，不跟随拍点。下文梦内律动档位只作为历史设计。

本文定义《入梦书》里"声音的节奏"与"画面的呼吸"如何对齐：开场时第一首 BGM 的鼓点要让整张页面产生**恰当的、被克制的心脏跳动感**，而不是做成音乐可视化插件，也不是让正文跟着抖。声音、画面、无障碍与性能四条线在这里签同一份合同，避免各文档各写一半而丢掉这段体验。

关联：[声音设计](AUDIO_DESIGN.md) 负责音频素材与播放语义，[界面与文字演出](UI_AND_TEXT_EFFECTS.md) 负责具体图层与文字表现，[素材指南](ASSET_GUIDE.md) 负责节拍图与清单落盘。冲突时以用户最新要求优先。

## 体验目标与边界

想要的感受：玩家打开梦斋，第一首曲子进来，画面像跟着呼吸一样轻轻起伏，鼓点落下时晕影和星点几乎同时收一下，人会先感到"这地方是活的"，之后才注意到自己在等一个故事。

必须守住的边界：

- 心跳是**装饰层**。它不承载任何剧情信息，关掉之后玩家不丢任何内容。
- 心跳**不进阅读区**。正文、姓名牌、选项文字在任何时刻都不缩放、不位移、不随拍改变透明度；阅读的稳定优先于律动。
- 心跳**不参与判定**。点击、推进、选择永不被量化到拍上，不等下一拍才响应，不因律动延迟一帧输入。
- 心跳**不闪**。任何全屏亮度变化幅度 ≤2%，可见脉冲频率 ≤2.0 Hz，不做频闪式明暗切换。
- 声音关闭时画面照旧律动。这是页面自身的节奏设计，不是"音频存在的证据"，因此静音、自动播放被拒、解码失败都不使律动消失（下文有独立时钟规则）。

## 节拍事实从哪来

首版**不做运行时频谱或实时节拍检测**。理由：手机上耗电、静音时拿不到信号、不同解码路径起点不一致，且检测误差会直接变成画面抖动。改为离线测一次、随资源发布。

每首需要驱动律动的曲目在制作阶段生成一份节拍侧车文件，与音频同目录，命名为音频文件名加 `.beats.json`，例如 `public/audio/bgm-theme.beats.json`：

```json
{
  "beatsVersion": 1,
  "assetId": "BGM_THEME",
  "audioFile": "bgm-theme.mp3",
  "sampleRate": 48000,
  "bpm": 72.0,
  "bpmConfidence": "high",
  "firstBeatSeconds": 6.072,
  "beatIntervalSeconds": 0.83333,
  "downbeatEvery": 4,
  "pulseDivision": 1,
  "beats": [6.072, 6.9079, 7.7439, 8.5798],
  "downbeats": [6.072, 9.4157, 12.7478],
  "encoderDelaySeconds": 0.023021,
  "timebase": "decodedPcmFfmpeg",
  "loop": {"mode": "fadeLoop", "startSeconds": 0.0, "endSeconds": 99.42, "overlapMs": 1667},
  "measuredBy": "ffmpeg spectral-flux onset + comb-filter tempo, 2026-09-12",
  "verifiedByHuman": false
}
```

字段规则：

- `beats` 是有效拍的绝对秒数，已扣除编码延迟，以解码后波形为基准。允许只给稳定段落，不必覆盖全曲；缺拍区间画面按最后已知 BPM 自由走。
- `bpmConfidence` 取 `high|medium|low`，由制作者按听测填写。`low` 时播放器只用 `bpm` 做自由时钟，不做逐拍对齐，避免把误差放大成抽动。
- `pulseDivision` 是"每几拍脉冲一次"。必须满足 `60 / (bpm / pulseDivision) ≥ 0.5` 秒，即可见脉冲 ≤2.0 Hz。曲子快于 120 BPM 时取 2 或 4，做半速/四分之一速跳动。
- `verifiedByHuman` 为 false 的节拍图只能在本地开发用；正式发布要求 true，且发布器校验 `beats` 单调递增、间隔离散度合理。
- 节拍图缺失或校验失败时，律动降级为**固定 72 BPM 自由呼吸**，不报错、不阻塞进入梦斋。这个兜底值与 `BGM_GATE` 的实测基本拍相同，属于巧合而非依赖：换曲后兜底值不必跟着改。
- `timebase` 记录节拍时间轴的测量基准，当前为 `decodedPcmFfmpeg`（ffmpeg 解码后的 PCM，起点已含编码延迟处理）。**浏览器 `decodeAudioData` 是否以同样方式处理 MP3 的 23.021ms 编码延迟尚未验证**；接入时必须实测首拍与画面的对齐，若有恒定偏移则在播放器侧统一补偿，不要去改节拍图里的实测值。

`BGM_GATE` 的节拍图已实测并落盘为 `public/audio/bgm-gate.beats.json`，结论如下：

| 项目 | 实测值 | 说明 |
|---|---|---|
| 基本拍 | **72.000 BPM** | 落在文档原定的 68–76 BPM 窗口内 |
| 细分层 | 143.6–144 BPM | 恰为基本拍的两倍，是八分音符层，不是基本拍 |
| 拍间隔 | 0.83333 秒 | 与 72 BPM 精确吻合 |
| 首个强拍 | 6.072 秒 | 前 6 秒是空气感铺底，没有可对齐的拍点 |
| 拍数 / 强拍数 | 112 / 28 | 覆盖 6.072–98.580 秒 |
| 强拍相位 | 每 4 拍的第 3 个偏移 | 该偏移的低频能量是其余三个的约 10 倍，判定明确 |
| 间隔抖动 | 标准差 4.8ms | 等于分析帧长（11.6ms）的量化误差，底层网格实际是刚性的 |
| 置信度 | `high` | 谱通量自相关峰 r=0.711 |

方法：22.05kHz 单声道、1024 点 FFT、256 样本跳距，取对数幅度谱的正向通量并减去 0.4 秒滑动均值，再用 1/2/3/4 倍梳状自相关择优。倍速歧义靠分频带解决——宽带（40Hz–8kHz）峰在 143.6 BPM，中频带（200Hz–2kHz）峰在 72.0 BPM，说明基本拍是 72，宽带峰来自细分层；强拍相位则靠低频带（40–200Hz）能量确定。

早期用 11.025kHz、256 跳距、纯 RMS 包络的粗测得到 147.6 BPM 且相关性仅 0.0002 量级（等于没有峰值），该结果已被上表取代，不要再引用。教训：包络法对这种低动态（LRA 1.7 LU）的柔和脉冲不够灵敏，必须用分频带谱通量。

`bgm_2`（→`BGM_THEME`）、`bgm_5`（→`BGM_END`）不驱动律动，因此不做节拍图；它们的早期粗测值（67.1 / 132.5 BPM）同样只是线索，未经复测，不得写进任何契约。

## 两个时钟

| 时钟 | 何时使用 | 行为 |
|---|---|---|
| `audioClock` | 目标曲目正在真实播放且节拍图 `bpmConfidence` 非 low | 以 `AudioContext.currentTime` 减去该曲的启动时刻得到曲内位置，再与 `beats` 对齐 |
| `freeClock` | 静音、自动播放被拒、音频解码失败、节拍图缺失或置信度低、页面刚恢复且尚未重新对齐 | 以 `performance.now()` 按标称 BPM 自增相位，不引用音频 |

切换规则：两个时钟之间**只做相位缓动，不跳变**。从 `freeClock` 接到 `audioClock` 时，取当前相位与目标相位差，在 ≤200ms 内以 ease-out 补齐；差值超过半拍时选更近的方向，宁可少走一拍也不倒退。切回 `freeClock` 时保留当前相位继续跑。

漂移校正：只在 `downbeats` 上校正一次，单次校正量 ≤40ms，超过则分多个小节摊平。禁止每帧对齐（会随解码抖动产生高频颤动）。曲目暂停、`silence`、页面隐藏期间停止校正并冻结相位。

## 脉冲包络

全站共用一个归一化包络 `pulse ∈ [0,1]`，每拍触发一次，形状取双搏（收缩—舒张），比正弦更像心跳、又比冲击包络温和：

| 阶段 | 相对拍首时间 | 目标值 | 缓动 |
|---|---|---|---|
| 一次上冲 | 0 → 70ms | 1.00 | ease-out |
| 部分回落 | 70 → 130ms | 0.32 | ease-in-out |
| 二次小搏 | 130 → 200ms | 0.48 | ease-out |
| 收束 | 200 → 380ms | 0.00 | ease-in |

总时长上限为 `0.6 × 拍间隔`，拍太快时按比例压缩而不是叠加两个包络。包络由单一 `requestAnimationFrame` 驱动器计算，写进一个 CSS 自定义属性（如 `--pulse`），各图层只读该值。禁止每个图层各自计时。

## 图层预算

各层的幅度是**上限**，不是建议值；调参只能往小。所有动画只用 `transform` 与 `opacity`，不碰布局属性，不对大面积图层挂 `filter: blur`。

| 图层 | 允许的变化 | 幅度上限 | 说明 |
|---|---|---|---|
| 场景图 | scale | 1.000 → 1.006 | 以画面中心为原点，不产生边缘露白 |
| 场景图 | brightness 或叠色 opacity | ±1.5% | 计入全屏亮度 ≤2% 的总额 |
| 晕影/边缘暗角 | opacity | ±0.05 | 心跳的主要可读来源 |
| 星点/微光装饰 | opacity | ±0.15 | scale ≤1.08，数量不因律动增加 |
| 书签 | translateY | ≤1.5px | 不旋转 |
| 纸卡 | 阴影模糊/扩散 | +2px 以内 | 纸卡本体不缩放、不位移 |
| 主按钮（如"开始入梦"） | 外发光 opacity | ≤0.06 | 不改变按钮尺寸与命中区 |
| 正文、姓名牌、选项、设置面板 | 无 | 0 | 明确禁止参与律动 |
| 刘看山 | 无 | 0 | 官方素材不做形变，仅保留自身 GIF 动作 |

多个图层同拍变化必须同相；不做"错拍营造层次"，那会读成卡顿。

## 出现在哪些页面

| 场景 | 律动 | 细则 |
|---|---|---|
| 入口/选梦（开场） | 有，强度 100% | 这是需求的重点。曲目进入后先给 2–3 拍的渐入斜坡，`pulse` 幅度从 0 线性升到满值，不在第一拍就满幅 |
| 故事详情 | 有，强度 60% | 阅读前的过渡，减弱以免与文字信息竞争 |
| 正在载入 | 有，强度 60% | 但不得暗示"AI 正在织梦"，仍按真实进度显示 |
| 阅读 | 无 | 仅保留场景图 ≤1.003 的极缓呼吸，与音乐无关，可由"关闭动画"一并关掉 |
| 选择 | 无 | 决策时不施加节奏压力 |
| 梦醒/梦签 | 单次，强度 40% | 进入时一次缓慢脉冲收束，随后静止，不持续跳 |
| 梦册、设置、回顾、错误 | 无 | 弹层期间冻结舞台律动 |

开场斜坡与首个起音的关系：`BGM_GATE` 的首个强拍实测在 **6.072 秒**，因此曲子起播后前约 6 秒画面保持静止呼吸，第一个拍点落下时才开始 2–3 拍的斜坡。这段"先安静再落拍"比原先估计的 2.8 秒长了一倍多，是刻意保留的：玩家先看到一个安静的梦斋，心跳才起来。不要用假节拍填满它，也不要为了"早点有反应"把斜坡提前。

注意首播淡入（1200–1800ms）与这 6 秒是两条独立的时间线：音量淡入在 0 秒就开始，律动斜坡等到 6.072 秒。两者不需要对齐。

## 降级与关闭

- `prefers-reduced-motion: reduce` 或用户"关闭动画"：`pulse` 恒为 0，所有图层取静态中间值，不做任何替代动画（不用颜色呼吸、不用音量指示器代偿）。声音开关与此独立。
- 自动播放被拒或用户静音：画面按 `freeClock` 继续律动，幅度不变。理由已在体验目标里说明。
- 性能保护：驱动器统计帧耗时，连续 2 帧超过 24ms 或 1 秒内平均帧率低于 50 时按序降级，恢复条件为连续 3 秒帧率回到 55 以上，且只回升一级。**档位由律动驱动器统一裁定，文字演出共用同一档位**，不各自测帧率、不各自降级——两套独立的降级逻辑会互相加剧掉帧。档位定义：

| 档位 | 律动 | 文字演出 |
|---|---|---|
| `full` | 全部图层（场景 scale + brightness + 晕影 + 星点） | 效果库全部可用 |
| `reduced` | 去掉场景 scale 与 brightness，只保留晕影 opacity | 粒子类（`particleGather`/`particleScatter`）跳过，其余保留 |
| `minimal` | 停用律动，记一次本地诊断，不弹窗 | A/B 类一律降级为 `fade`，C 类停止 |

档位变化对玩家不可见地生效，不提示、不中断阅读。当前档位由 `pulse` 模块导出，`effects` 模块读取而不写入。
- 页面隐藏（`visibilitychange`）：立刻停驱动器与相位推进，不在后台空转；回来后从 `freeClock` 起跑并按上文缓动重新对齐。
- 电量/省电模式若可探测，按性能保护的最低档（`minimal`）处理。
- **只有带节拍图的曲目驱动律动。** 当前仅 `BGM_GATE` 有 `bgm-gate.beats.json`；`BGM_THEME`/`BGM_DREAM`/`BGM_END` 及新增的长曲变体（`BGM_LONG_*`）都没有节拍图，播放这些曲目时律动走 `freeClock` 固定 72 BPM 自由呼吸，**不做运行时节拍检测**。变体若日后需要驱动律动，必须离线测量并随该变体发布自己的侧车文件；段落切片会改变首拍位置，不能沿用母曲的节拍图。

## 无障碍

- 律动层整体 `aria-hidden`，不进无障碍树，屏幕阅读器不播报任何节奏状态。
- 不依赖律动传达状态：加载中、可点击、已保存都必须有文字或静态视觉。
- 全屏亮度变化 ≤2%、脉冲 ≤2.0 Hz，用于避开闪光相关风险；红色大面积闪烁一律禁止。
- 触控命中区不随律动变化，按钮的 44×44 CSS px 下限按静态尺寸计算。
- 200% 缩放与 360px 宽度下律动幅度按比例缩小，不允许因缩放放大成明显晃动。

## 验收

1. 静音打开首页：画面有 ≤2.0 Hz 的轻微起伏，无声音，无报错。
2. 开启声音：前 ~2.8 秒安静，鼓点进入后 2–3 拍内律动升到满幅，肉眼看鼓点与晕影收缩同时发生（允许 ≤50ms 主观误差）。
3. 连听三分钟（含至少一次循环接缝）：不出现相位跳变、不出现忽快忽慢、循环处画面不顿。
4. 开"关闭动画"：律动完全消失，页面仍可用，声音仍可独立开关。
5. 中低端手机与 360px 宽度：帧率不低于 50，或按降级规则自动退档且不报错。
6. 正文与选项在任何拍上截图对比：像素级不位移、不改字号。
7. 切出页面 30 秒再回来：不出现补跳、不叠加脉冲、不重播音效。
