# 入梦书

读过的故事，值得一活。入梦书是一款中文互动小说阅读器：在故事中做选择，回望分歧，收藏属于自己的梦签。

[在线体验](https://uangsc.github.io/dream-entry-book/) · [部署说明](docs/FC_DEPLOYMENT.md) · [入梦书格式](docs/DREAMBOOK_FORMAT.md)

首篇《吃人心的小妖怪》取材于知乎作者女巫的作品节选，包含三条路线、14 个选择点、51 个节点、1993 段对白与旁白、8 个终幕。原作与作者入口可在游戏“关于这场梦”中查看。

**版权与内容声明：**内置互动剧情由 AI 基于原作素材生成与改编，属于衍生演绎，非原创故事，也不代表原作全文或原作者的官方续作。仅供娱乐体验，不用于任何商业用途。原作与相关素材的权利归原作者及各自权利人所有。

## 当前功能

- 沉浸阅读：人物立绘、场景切换、配乐、环境音、文字演出与自动播放；支持减少动态效果。
- 对话回看：最多保留 30 条前后对话记录；重选分歧后清除旧路线的前进记录，并重建剧情条件。
- 两个存档位：自动档在选择出现时保存到前一句对话，下个选择覆盖；手动档可随时保存。存档携带回看队列，退出续读位置独立保存。
- 两种旁白表现：立绘渐变模式缩小并淡白处理最近角色；文本旁白模式展示大字旁白或无立绘角色姓名。心声用括号和主人公立绘表达。
- 授权门槛：开始、继续游戏、书架、导入导出、存档及设置等功能，均需先登录并完成知乎授权。游客可停留首页、调整声音和查看作品说明。
- 本地书架：导入、导出 `.dreambook`，收藏梦签，备份阅读进度。素材可以缓存，但缓存与本地存档不能替代登录授权。
- 知乎接入：提供登录、活动故事目录、搜索与直答线索分析入口，需要单独部署并配置后端。任意小说自动制作游戏目前是明确标注的流程演示。

## 如何游玩与保存

先点击“知乎登录”并完成授权，再点击“推开梦门”开始阅读。未登录点击受限入口会提示授权，不会直接开始游戏或导入文件。正文、右箭头、空格或键盘右方向键继续；左箭头或键盘左方向键回看。自动播放遇到选择会暂停，语速、声音与旁白样式可在设置中调整。

自动档读取后停在选择前的最后一句，再点继续才出现选项。回退不重复结算选择；重新选择会替换后续路线，梦签收藏独立保留。

书架、存档、梦签和声音偏好保存在当前浏览器。清除网站数据、换浏览器或换设备不会自动同步；重要进度请在设置中导出备份。知乎登录也不等于云存档。素材包导出不包含玩家进度。

浏览器可能在刷新后要求再次点击页面才播放声音；只要到达首页时声音尚未开启，就会提示开启。登录状态在打开页面、回到标签页及页面可见期间定期向服务端确认；会话无法确认时需恢复网络并重新确认授权。页面提供“新版本已备好，更新书页”时，点击更新并刷新即可使用新版。

## 本地运行

前端需要 Node.js 22.12+ 或 24。预览首页可只启动前端，进入游戏需要可用的账号后端；本地开发可用后端模拟登录，线上使用真实知乎授权。

```sh
npm ci
npm run dev -- --host 127.0.0.1 --port 62560 --strictPort
```

打开 [http://127.0.0.1:62560/](http://127.0.0.1:62560/)。预览发布版本：

```sh
npm run build
npm run preview
```

本地账号与内容接口服务另需 Python 3.12。Windows 示例：

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r backend/requirements.txt
.venv\Scripts\python -m uvicorn backend.app:app --host 127.0.0.1 --port 62561
```

Linux/macOS 使用 `.venv/bin/python`。Vite 将本地 `/api` 转发到 62561。后端默认提供模拟登录；真实知乎配置见 [账号服务](backend/README.md) 与 [API 指南](docs/API_GUIDE.md)。本地密钥由维护者自行填入被忽略的 `.env`，应用可以读取，开发助手不得读取；密钥禁止进入前端和 Git。

## 部署

前端部署在 GitHub Pages，推送 `main` 后由 GitHub Actions 自动检查、构建并发布 `dist/`。仓库 Settings → Pages 的构建来源选择 **GitHub Actions**。公开变量 `VITE_API_BASE_URL` 指向 FC HTTPS 域名，不能包含 `/api`、查询参数或密钥；未设置时使用工作流内的演示后端地址。

后端部署在阿里云 FC，业务代码与依赖层分别上传。推送 GitHub **不会自动更新 FC**。仅更新前端和素材通常只需 push；涉及后端代码、依赖或示例书包层时，按 [FC 部署说明](docs/FC_DEPLOYMENT.md) 更新相应包。

真实登录的知乎回调地址为：

```text
https://uangsc.github.io/dream-entry-book/oauth-callback.html
```

当前后端使用 FastAPI、SQLite 和单进程任务队列。FC 临时磁盘不保证持久化，多实例不共享任务、记录与额度预算；长时间后台分析尚不能视为可靠生产任务服务。剧情和存档保存在浏览器，登录检查仍依赖后端。前端门槛控制正常使用流程，不是对公开静态素材的保密保护；后端接口仍单独验证会话。

## 检查与内容制作

```sh
npm test
npm run check:release
npm run test:repository
npm run check:repository
npm run build
npm run check:repository -- --dist
npm run test:offline
```

`npm test` 自动编译正文并验证全部路线，再运行测试。`check:release` 检查剧情与素材完整性；附加 `-- --public` 会核对审读及素材使用依据，当前演示素材的待确认项不会被自动标为通过。

构建只读取 `content/final/sources.json` 登记的四份剧情正文，以及必要的故事基础数据、资源清单与发布素材。临时报告生成到 `.work/story/`。修改剧情内容或逻辑时须更新来源哈希和 `buildId`；这次仓库清理保留原剧情构建号以兼容既有存档。

旧 Demo 和旧单线 `.dreambook` 保留为导入兼容样例，其中 Demo 也用于格式测试。原始音画制作脚本仍可使用本地素材，但素材原件不属于公开仓库或 Pages 构建依赖。

公开文档见 [文档目录](docs/README.md)。提交范围、检查方法和本地文档约定见 [仓库发布规则](docs/REPOSITORY_POLICY.md)。
